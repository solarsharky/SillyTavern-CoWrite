# 共笔（CoWrite）

一个面向中文 SillyTavern 用户的独立共创记录扩展。你可以和当前角色轮流答问卷、评价彼此的答案，或持续写交换日记；所有内容都留在共笔工作区，不会新增、修改聊天楼层。

> 当前版本：`v0.1.0-beta.11`。这是公开测试版，请先备份重要记录再更新。

## 环境要求

- SillyTavern `1.12.13` 或更高版本
- [酒馆助手 / JS-Slash-Runner](https://gitlab.com/novi028/JS-Slash-Runner) `4.9.3` 或更高版本
- 当前版本只支持单角色聊天；群聊中只能只读浏览记录
- 中文界面

## 安装

1. 确保酒馆助手已经安装并启用。
2. 打开 SillyTavern 的“扩展”面板，选择“安装扩展”。
3. 粘贴仓库地址：

   ```text
   https://github.com/solarsharky/SillyTavern-CoWrite
   ```

4. 安装后重新加载页面。右侧会出现可拖拽的 `✏️` 悬浮按钮。也可以从左下角魔法棒菜单的“共笔”，或扩展设置里的标准“共笔”折叠栏打开。

仓库的 `main` 分支始终保留可直接安装的 `manifest.json` 与已构建 `dist/`，不需要在本地安装 Node.js。

共笔不再通过 manifest 按酒馆助手的安装文件夹名硬拦截加载；不同安装源可能使用不同文件夹名。打开后仍会在运行时检查酒馆助手是否存在以及版本是否达到 4.9.3。

## 三种内置玩法

### 双人问卷

Char 首轮默认准备 10 道题，同时填写自己的答案；“生成更多题”默认每次追加 10 题。每道题的双方答案按相同题型配对展示：电脑端并排，手机端通过“我的答案 / 他的答案”页签切换，默认显示我的填写区；切换不会清空正在填写的内容。Char 的答案只读，User 的输入保持空白。填好后点击“交给他写”，Char 的评价或批改会直接显示在对应的 User 答案下面。题目数量、顺序和每一阶段的行为都可以在格式分类中修改。

内置“依恋类型”采用 10 道 1—5 分量表题。答完后，Prompt 会要求模型先逐题点评，再分别给出 User 与 Char 的维度得分、主要依恋类型倾向、具体答案依据，以及双方的相处建议。设计参考[依恋焦虑与回避两个维度](https://labs.psychology.illinois.edu/~rcfraley/measures/ecrr.htm)；题目与分界规则属于本插件的趣味自测设计，不是标准心理量表。更新后的新测试会使用此流程，已有记录保留原内容要求。

### Char 给 User 的问卷

Char 以自己的口吻默认出 10 道题，“生成更多题”默认每次追加 10 题；User 使用短答、长答、单选、多选或量表作答。每道题的完整题干直接显示在输入卡片上；点击“交给他写”后，Char 会在每道已答题下面评价，并可附上总结。

### 交换日记

Char 写开篇，User 接着手写一页。此后每次“交给他写”都会让 Char 回应上一页、写下自己的下一篇，再留出新的 User 长文本位置；也可以点击“再写一页”追加新的日记。

## 当前记录的四个操作

- **交给他写**：把已填写的内容交给 Char，让他按玩法作答、评价或续写。旧版已完成或归档的记录也可以继续填写和生成，不需要重新打开。
- **重roll**：重新生成 Char 最近一次写的内容，成功后才替换。失败或停止会保留原内容；若该次生成的新题中已有手填答案，会先提示这些答案也会被清除。
- **清空重填**：保留原题（包括追加的新题）和随题生成的 Char 答案，清空所有 User 填写及后续回应、评价，确认后即可重新填写。
- **生成更多题**：保留已有内容，在同一份记录末尾追加一组新题。交换日记中显示为“再写一页”。

填写会自动保存，不再需要点击“完成”或“归档”。旧版未修改过的内置流程会自动更新；已有记录中的原始答案仍会保留。

## API 输出与全局 Prompt

- 在“设置 → 生成连接”中，每个 API 都可独立选择“流式输出”或“非流式输出”，包括跟随 SillyTavern 的连接。默认保持非流式；选择后点击“保存设置”。流式模式显示接收进度，完整结果返回并校验后统一显示题目；停止或失败不会写入半成品。
- 在“设置 → 全局 Prompt”中，分别填写“最开头的 Prompt”和“最结尾的 Prompt”，两者可以同时生效。发送顺序为前置 Prompt → 其他提示词与当前记录 → 后置 Prompt；支持 `{{char}}`、`{{user}}`、`{{round}}`、`{{record_title}}`。留空不插入，关闭启用后保留内容。
- API 输出模式和全局 Prompt 对首轮、角色作答、重roll、补题、自动修复和长记录摘要均生效；新旧记录统一使用当前设置。这些设置会随整库备份保存。

## 数据与安全

- 主数据使用 SillyTavern 账户文件：`cowrite-catalog.json`、`cowrite-templates.json` 和独立的 `cowrite-record-<uuid>.json`。
- 浏览器本地会保存缓存和未同步草稿。服务器保存失败时，界面会明确显示“未同步”，刷新后仍可恢复并再次保存。
- 自定义 API Key 默认只存在当前页面会话。只有主动勾选“记住密钥”后，密钥才会以明文保存在当前浏览器本地。
- API Key 不会进入账户文件、整库备份、模板/记录导出、构建产物或共笔日志。提交 Issue 前仍请自行检查并脱敏浏览器控制台内容。
- 独立连接会把你选择的角色卡、Persona、场景、近期聊天、世界书和当前记录发送给对应 API 服务。只应使用你信任的服务商和 Base URL。
- 问卷、双方答案、评价和交换日记始终只写入共笔账户文件与本地待同步草稿；插件不会把任何生成结果新增或注入聊天楼层。
- AI 输出只能追加 Char 内容、评价与空白 User 输入卡；不能覆盖已有 User 答案。无效输出会自动修复一次，仍失败则不会修改记录，并可下载原始响应排查。

## 备份与恢复

进入“设置 → 备份与恢复”，点击“下载整库备份”。备份是带 `schemaVersion` 的 JSON，包含所有格式分类、内容项、记录和不含密钥的设置。导入时会校验结构，并为冲突的分类/记录 ID 自动生成新 ID。

单份记录可从记录库导出 JSON 或 Markdown；单个格式分类也可以单独导入、导出。建议在更新扩展、清理浏览器数据或批量整理记录之前下载整库备份。

## 格式分类、内容与上下文

模板库采用两级结构：“分类”就是玩法格式，例如双人问卷、Char 给 User 的问卷和交换日记；每个分类下面可以有任意数量的内容项，例如依恋类型、星座、私密话题或一组必须包含的题目。分类与内容项都可以新增、编辑和删除，点击某个内容项即可直接开始。

内容项只描述“写什么”，适合填写主题、尺度、语气、禁区和必须出现的题目。分类格式负责共同规则、首轮流程和继续流程，支持 `{{char}}`、`{{user}}`、`{{round}}` 和 `{{record_title}}` 变量。核心 JSON 格式协议单独放在分类编辑器的高级区域，并需要确认风险后才能修改。

历史聊天条数、当前激活世界书、手选世界书条目、长记录预算和默认连接统一放在“设置”，对所有分类、新记录、角色作答、重roll和追加内容生效。当前激活世界书通过 SillyTavern 的 `world_info_before` / `world_info_after` 位置读取；手选条目会在发送前再次排除停用或已删除条目。上下文只供模型参考，响应仍只写入共笔记录。

生成过程中窗口右下角始终显示“停止本轮”。停止后即使服务端稍后返回内容，插件也会丢弃该响应，不保存半成品。

核心 JSON 协议默认只读。高级模式允许在确认风险后覆盖协议，但结构校验、User 内容保护、引用校验和追加事务不能关闭。

记录超过 `min(12,000 tokens, ST 最大上下文的 40%, 全局长记录预算)` 后，共笔会先为较早轮次生成滚动摘要；后续请求仅发送摘要、最近三轮及尚未回答/评价的输入，完整历史仍保存在记录文件中。摘要失败时不会继续主生成，可以重试；若记录无法继续压缩，可调整设置中的预算或从模板库新建记录。

## 开发

```bash
npm install
npm run check
```

源码采用 Vue 3、TypeScript、Pinia、Zod、Vite、Vitest。`npm run build` 会生成需要提交的 `dist/index.js` 和 `dist/index.css`。CI 会检查提交的构建产物是否和源码一致。
